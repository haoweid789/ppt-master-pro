# 说人话完整规范(ppt-master-pro / references)

让 AI 不说 AI 腔:幻灯片文案、演讲备注、叙事结构、用户沟通四个层面的完整规范。
核心原则(源自 anti-defensive-writing 正面化):**围绕最强的证据组织内容,把优势明确说出来,主张与证据严格对齐。**

---

## 一、幻灯片文案(观众 3 秒 rule)

观众扫一页的时间约 3 秒。文案的任务是让他在 3 秒内拿到一个具体主张。

### 1.1 改写对照库

| AI 腔(禁用) | 人话(改写方向) |
|---|---|
| 深度赋能多场景应用生态 | 已接入 3 条产线,单线月省 11 万 |
| 构建全链路数字化闭环 | 从下单到出货,一个系统盯全程 |
| 多维度全方位提升用户体验 | 客诉响应从 48h 压到 4h |
| 抢占行业新赛道,引领变革 | 明年做到区域前三,份额 15% |
| 依托核心算法引擎驱动创新 | 换了匹配算法,点击率翻倍 |
| 显著提升了系统性能 | 峰值并发从 2k 到 9k |
| 存在一定优化空间 | 高峰期丢包率 3%,高于 1% 目标 |
| 完善的风控体系保障安全 | 上线半年拦截可疑交易 4.2 万笔 |
| 深受广大用户好评 | 应用商店 4.8 分,12 万条评价 |
| 未来可期 | 三年内 replicas 成本降到现在的 40% |

改写公式:**具体数字 / 具体对象 / 具体结果**。没有数字时退而求其次:名字、地点、机制、对比、时间。

### 1.2 硬规则

1. **一页一句主张**:主张句是可争论的断言("华南渠道贡献 62% 增量"),不是话题标签("渠道分析")。听众看完能说出"哦,所以呢——原来是这个意思"。
2. **形容词是欠条**:"显著、大幅、行业领先、深度赋能"= 没给量。要么给数字,要么给事实,要么删。
3. **砍掉正确的废话**:任何一页删掉后听众信息量不变的文字,都该删。
4. **实质先于样式**:深度来自选最锐利的事实并砍掉其余,不来自塞更多文字。
5. **口语化有度**:内部分享可以口语;对外汇报、学术答辩保持术语准确但句子仍要短。

### 1.3 检查(每页过一遍)

- 这页的主张句能被人复述出来吗?
- 有没有一个数字/事实是别处拿不到的?
- 删掉一半文字,主张会变弱吗?(不会→继续删)
- 有没有"赋能/抓手/闭环/生态/维度"这类词?(有→改写)

## 二、演讲备注(讲的人的话)

备注是给**讲的人**的提词卡,不是幻灯片文字的复读机。

### 2.1 三段式模板

```
① 开口:这页第一句说什么(钩子/承接上一页/直接抛结论)
   例:"刚才说了成本降了三成,这页讲代价是什么。"
② 强调:哪个数字/词要停顿、放慢、重复
   例:"62% 这个数停两秒——它说明我们不是靠铺量。"
③ 预判:可能被问到的问题 + 一句应答
   例:"如果问竞品为什么没做:他们的数据口径对不上,见附录页。"
```

### 2.2 规则

- 每页备注非空;禁止复制幻灯片文字
- 备注里可以写人话的口语版,幻灯片上写精炼版——两者不同层
- 过渡句写进下一页备注的开头("讲完痛点,接下来是我们怎么解")

## 三、叙事说人话(优势原则)

论文、汇报、路演是**发布会**,不是工作日志。观众要的是"为什么值得信",不是"你经历了什么"。

### 3.1 叙事规则

1. **只围绕优势组织内容**:找到真正领先/独特/不可替代的部分(新能力、更低成本、更好扩展、更有意义的权衡),围绕它建立叙事。没形成优势的内容不进主线。
2. **不写流水账**:不按"先做了什么、后来试了什么、哪些失败"展开。只保留最终成立的逻辑:问题为什么重要 → 现有方案为什么不够 → 我们提供了什么 → 证据如何支持。
3. **打不过的维度不设为战场**:某指标不占优,就换任务定义/评价口径/适用场景,讲我们赢的那场比赛。明确"我们赢的是这个",不去争不属于我们的冠军。
4. **优势要明说**:不指望听众自己从表格里发现。主动讲:在哪个条件下最好、为什么、解决了什么实际问题。
5. **主张与证据对齐**:说服力来自主张被证据牢固支撑,不来自比较项目数量。只提证据撑得住的话。

### 3.2 语言防自我削弱

- 禁用:"遗憾的是""仅""仍明显落后""效果有限""存在严重不足"
- 不说输:不占优的结果按序判断——①必须讨论吗 ②能否换个目标/约束解释 ③是否是合理权衡 ④能否收缩主张 ⑤是否该调整故事主线
- 局部现象不上升为整体缺陷;不替听众完成对己方不利的推理

### 3.3 结构规则

- **开场四件事快速建立**:重要且未解决的问题 → 现有方案的关键缺口 → 我们独特的思路 → 最有分量的结果
- 不从实现细节和研究过程开头;贡献未建立前不提前讨论不足
- **结论只强化记忆点**:解决了什么、提出了什么、证明了什么、为什么重要。结尾不突然自我否定、不扩大局限性

### 3.4 交稿自查(不递刀子)

- [ ] 这句话是否无意中扩大了要承担的责任?
- [ ] 是否提出了没人要求回答的问题?
- [ ] 是否把局部现象说成普遍缺陷?
- [ ] 有没有按"我们做了什么"的过程在展开?
- [ ] 开场五句里,问题和主张都出来了吗?
- [ ] 结论里有没有突然的自我否定?

## 四、与用户沟通说人话

- 第一句给结果/交付物,不绕"好的,我来帮您…"
- 进度汇报给事实:页数、文件路径、检查结果、下一步
- 出问题:一句真话说明 + 已走的替代路径 + 当前交付状态;不铺陈困难、不写小作文
- 问最多一个真正影响下一步的问题,且工作已经先动手

## 五、备注与讲稿速查

| 场景 | 幻灯片风格 | 备注风格 |
|---|---|---|
| 工作汇报 | 结论先行,数字大字化 | 每页:结论 → 依据 → 下一步请求 |
| 学术答辩 | 证据链,图表+来源 | 方法细节备查,预判提问逐条写 |
| 商业路演 | 痛点-方案-市场-团队 | 钩子开场,每个数字配一句"所以呢" |
| 教学培训 | 循序渐进,示例先行 | 讲解词全写,含互动提问 |
